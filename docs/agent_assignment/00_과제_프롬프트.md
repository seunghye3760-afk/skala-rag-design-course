## 2. 패턴 선택 — Orchestrator-Workers (권장)

**선정 이유**: 현재 그래프가 이미 "작업 분배(Send) → 병렬 worker → reducer 누적 → join → synthesize"
구조라서 Orchestrator-Workers의 필수 항목까지의 거리가 가장 짧다. Supervisor로 가면
`balance_check`를 LLM 라우터로 바꾸고 관점 에이전트 4개를 각각 노드로 분리해야 해서 변경 폭이 크다.
(Agent-as-Tool·Swarm은 과제에서 제외.)

### 2.1 필수 항목 ↔ 구현 위치

| 노션 필수 항목 | 지금 상태 | 해야 할 것 |
|---|---|---|
| 서브 태스크 목록을 **구조화**해 State에 저장 | `fan_out_collect`가 루브릭×기술로 Send를 즉석 생성, State에 계획 없음 | `plan_tasks` 노드 신설 → `task_plan: list[SubTask]`를 State에 저장. `SubTask(task_id, tech_id, criterion_id, channels, round, status, reason)` |
| Workers는 **계획 수립 이후** 결정 = Dynamic Fan-out | 항상 36개(또는 `--criteria`) 고정 | `route_after_plan`이 `task_plan`에서 `status == "pending"`인 것만 Send. 계획은 **LLM 플래너**가 `tech_briefs`·루브릭·이전 라운드 사유를 보고 항목마다 기술별 채널(논문 RAG / 웹 / 오픈소스)과 쿼리 템플릿 쌍 수(= worker 수)를 정한다 → fan-out 수가 모델 결정, 실행마다 달라짐. 코드는 커버리지·대칭·상한 가드만 |
| Workers 결과 누적 + **synthesizer** 집계 | `operator.add` reducer, `synthesize_report` | 유지. `task_plan` 상태 갱신용 reducer 추가 |
| 일부 worker 실패 시 **계속/재시도/제외** 중 택일 = Fallback | `score_task`는 형식 오류 1회 재요청, `collect_evidence`는 예외를 삼키고 빈 결과 | 정책을 **명시**: `collect_evidence` 실패 → 1회 재시도 → 실패 시 **제외**하고 `info_gaps`에 기록(`status="excluded"`, `last_error`). `score_task` 실패 → 1회 재시도 → 해당 항목 `NA` + `info_gaps`. `configs/runtime.yaml`에 `fallback.policy`로 적는다 |
| 하위 에이전트 간 직접 통신 금지 | 이미 없음 (worker는 State만 반환) | 유지, README에 명시 |

### 2.2 순서 하드코딩 금지 / 스텝 고정 금지 (공통)

- `add_conditional_edges`로 분기하는 곳: `plan_tasks → (계획 결과) fan-out`, `balance_check → route_after_balance`, `evaluate_report → route_after_quality`.
- "몇 번 돌면 끝"이 아니라 **상태 조건**(pending task 0개, retry_targets 비어 있음, 품질 통과)으로 종료. 상한(`max_rounds`)은 안전장치일 뿐.
- 수업 기준 "Agent ≠ Loop": 루프가 있어도 구조가 코드로 고정되면 Workflow다. **모델이 런타임에 결정하는 지점**을 최소 두 곳 남긴다 — (a) `plan_tasks`의 서브태스크 분해(채널·쿼리·worker 수, 재시도·재계획 시 사유 반영), (b) `judge_node`의 품질 판정. 그 외 라우팅은 코드(결정론)로. 규칙이 계획을 "만드는" 경로는 LLM 실패 시 비상 기본 계획뿐이다.
- Replan이 잦아지면 Supervisor로 수렴한다(수업 2-(2)). Replan은 품질 평가 미달 때만, 최대 2회.

### 2.3 수업 설계 프레임워크로 다시 쓰기 — Goal → Plan → Execute → Reflect

README·설계 근거에 이 순서로 적는다. (수업 3-2 Design Framework)

**Goal (Desired Outcome + Success Criteria)**

| 구분 | 내용 |
|---|---|
| 대상 | TurboQuant(SW)·CXL-PNM(HW)의 AI 데이터센터 장문 LLM 추론 적용 |
| 변화 | 데이터센터 운영자가 두 기술을 4관점 근거·조건·상충·공백 기준으로 판단할 수 있는 보고서 1부 |
| 결정/행동 | 어느 시나리오에 어떤 조건으로 검토할지 결정 (우열·순위는 결정 대상 아님) |
| 범위 | 루브릭 18항목, 2025-01 이후 공개 자료, 논문 2편 + 웹. 미공개 벤치마크·추정치 제외 |

| Success Criteria | 판정 가능한 기준 | 측정 위치 |
|---|---|---|
| 근거성 (Quality) | 본문 인용 evidence_id의 100%가 `evidence_pool`·REFERENCE에 존재 | `evaluate_report` 규칙 |
| 충실성 | 본문 수치가 인용 근거 excerpt에 존재(문자열 대조), Judge groundedness ≥ 4/5 | 규칙 + Judge |
| 완결성 | 기술 2 × 관점 4 모두 NA 아닌 결과 ≥ 1, SUMMARY·REFERENCE 존재 | 규칙 |
| 일관성 | `intra_conflict` 미표기 상반 근거 0건, 금지 표현(우열·추천·순위·총점) 0건 | 규칙 |
| Formatting (Constraints) | 설계서 E 목차, PDF ≤ 10장 | `reporting/pdf.py` 쪽수 검사 |
| Compliance | 근거 없는 수치·출처 생성 금지, 두 기술 동일 검색 규칙 | `rules/`, `query_rules` |
| Cost (Operational) | 수집 worker ≤ 36 + 재시도분, 채점 ≤ 8×3, Judge ≤ 3회, 전체 LLM 호출 상한을 `runtime.yaml`에 명시 | `step_count`, LangSmith |
| Error Handling | 근거 미검색 → 임의 생성 금지, `info_gaps` 기록 후 진행 | fallback 정책 |
| Consistency / Stability | 같은 입력 3회(K=3) 실행 시 품질 평가 PASS 유지, 무한 루프 0 | 제출 전 PassK 확인 |

**Plan — Task Decomposition (처리 방식 / 실패 처리 / Success Criteria 연결)**

| # | Task | 처리 | 실패 처리 | 연결 기준 |
|---|---|---|---|---|
| 1 | 기술 조사 (`tech_research`) | 논문 RAG + LLM | 인덱스 없음 → 웹만, brief 비면 info_gap | 범위 |
| 2 | **계획 수립 (`plan_tasks`)** — 셀(기술×항목)별 채널·쿼리 템플릿·worker 수를 `task_plan`으로 | LLM 플래너 + 코드 가드 | LLM 실패 → 1회 재시도 → 루브릭 기본 템플릿 비상 계획 (decision_log 기록) | 완결성 |
| 3 | 근거 수집 worker (`collect_evidence`) × N | 논문 RAG / Tavily / 원문 확인 | 1회 재시도 → 제외 + info_gap, `node_status=excluded` | 근거성, Compliance |
| 4 | 관점 채점 worker (`score_task`) × M | LLM, 구조화 출력 | 형식 오류 1회 재요청 → NA + info_gap | 충실성 |
| 5 | 균형 점검 (`balance_check`) | 규칙 | 재검색/재채점 대상 지정, `retry_round ≤ 2` | 편향 통제 |
| 6 | 규칙 적용 (`apply_rules`) | 규칙 | — | 일관성 |
| 7 | 종합·보고서 (`synthesize_report`) | LLM + 조립 | PDF 실패해도 MD는 생성 | Formatting |
| 8 | **품질 평가 (`evaluate_report`)** | 규칙 → Judge | 미달 → 항목별 복귀, `quality_round ≤ 2` 후 미달 기록·종료 | 4항목 전부 |

**Control Strategy**: 분기는 전부 설계자의 정책. Rule 분기(`route_after_balance`, `route_after_quality`, fallback)와 Judge 분기(`evaluate_report` 안의 LLM 판정)를 구분하고, Judge는 판정만, 라우팅은 순수 함수로(§4.4).
**Retry & Termination**: `retry.max_rounds=2`, `quality.max_rounds=2`, `recursion_limit`, LLM 호출 상한 — 전부 코드 상수. 근거 부족 시 응답 규칙 = info_gap, 비용 초과 시 = 현재 결과로 보고서 생성 후 종료.

**Execute**: worker는 자기 Send 입력만 읽고 자기 키만 쓴다(State Ownership). 원문 raw는 `.cache/`·`outputs/runs/`, State에는 Evidence(구조화)만.
**Reflect**: Tool-based(규칙) + External Judge(LLM) 2단. Self-reflection은 쓰지 않는다(채점 재현성).

## 3. State Schema — 7개 항목 설계 근거 (README에 그대로 옮긴다)

수업 4-2-1-(5) **Layered State(A. Orchestrator-Workers)** 를 따른다. "State는 인터페이스이지 컨테이너가 아니다" — 보고서 본문은 파일로, State에는 경로만.

```python
class OrchestratorState(TypedDict, total=False):      # 상위: 흐름 제어 + 취합
    # 제어 메타
    run_id: str                                        # 상관 키 (LangSmith metadata, decision_log, outputs/)
    task_plan: Annotated[list[SubTask], merge_tasks]   # 구조화된 서브태스크 목록, task_id 기준 최신 상태
    retry_round: int; quality_round: int; step_count: Annotated[int, operator.add]
    status: Literal["RUNNING", "SUCCESS", "PARTIAL", "FAILED"]
    node_status: Annotated[dict[str, str], merge_dict] # task_id → pending|done|failed|excluded
    errors: Annotated[list[dict], operator.add]        # {"task_id", "node", "type", "message", "ts"}
    retry_targets: list[RetryTarget]; quality_verdict: QualityVerdict | None
    # 페이로드 (worker 결과 취합 — 취합 ≠ 종합)
    evidence_pool: Annotated[list[Evidence], operator.add]       # raw 근거, 압축 금지·누적만
    criterion_results: Annotated[list[CriterionResult], operator.add]
    tech_briefs: dict; final_results: list; trl_results: list; conflicts: list
    final_assessment: dict; report_path: str                     # 보고서 본문은 파일, 경로만
```

worker(`collect_evidence`, `score_task`)는 Send로 받은 `CollectTask`/`ScoreTask`만 읽고(WorkerState 역할), 자기 키(`evidence_pool`, `search_log`, `criterion_results`, `node_status`, `errors`)만 반환한다. 기존 `MainState`는 수정하지 않고 `orchestrator/state.py`의 `OrchestratorState`가 같은 페이로드 키를 포함한다 (contract PR 불필요, §5.1과 일치).

| 항목 | 설계 답 | 코드 |
|---|---|---|
| 제어 vs 페이로드 분리 | 페이로드: `technologies, domain, rubrics, tech_briefs, evidence_pool, criterion_results, final_results, trl_results, conflicts, final_assessment, report_path`. 제어: `run_id, only_criteria, task_plan, retry_round, retry_targets, quality_round, quality_verdict, step_count, node_status, last_error` | `graph/state.py` |
| 관측성 위치 | 라우팅·재작업 **사유의 요약**만 State(`RetryTarget.reason`, `SubTask.reason`, `quality_verdict.reasons`)에 둔다. 결정 로그 본문·프롬프트·토큰은 **LangSmith 트레이스 + `outputs/runs/<run_id>/decision_log.jsonl`** 로 뺀다 | `progress.py` 확장(`decision()` 함수), LangSmith |
| 지속성 비용 | `evidence_pool`은 채점에 필요하므로 State에 두되 round ≤ 2 + `duplicate_group` 중복 제거로 상한. 원문 전문·검색 캐시는 `.cache/`·`outputs/runs/`에만. 안 쓰는 `messages` 키 제거 | `graph/reducers.py`, `evidence/collect.py` |
| 상관 | `run_id`가 상관 키. `graph.invoke(init, config={"run_name": run_id, "metadata": {"run_id": run_id}, "tags": [...]})`로 LangSmith에 전달, `decision_log.jsonl`·보고서 파일명에도 같은 값 | `app_agent.py`, `orchestrator/observability.py` |
| 재개/복구 | `MemorySaver`(또는 `SqliteSaver`) 체크포인터, `thread_id = run_id`. `node_status[task_id]`(pending/done/failed/excluded)와 `last_error`로 실패 지점 식별, worker 1회 재시도 | `graph/main.py` compile, `dispatch.py` |
| 동시 처리 | 병렬 worker가 쓰는 키는 전부 reducer: `evidence_pool`·`search_log`·`criterion_results`(`operator.add`), `node_status`(dict merge), `task_plan`(task_id 기준 최신 상태 덮어쓰기) | `graph/state.py`, `graph/reducers.py` |
| 종료 보장 | `retry_round ≤ retry.max_rounds(2)`, `quality_round ≤ quality.max_rounds(2)`, `step_count` 상한, `recursion_limit` 설정. 한도 도달 시 미달 항목을 보고서에 "정보 공백/미달"로 적고 **정상 종료** | `rules/balance.py`, `orchestrator/quality.py`, `configs/runtime.yaml` |

## 4. 보고서 품질 평가 노드 (필수, 신규)

`synthesize_report` 뒤에 `evaluate_report` 노드 추가, 결과를 `quality_verdict`에 저장, 미달 시 Loop.

### 4.1 평가 항목과 판정 (Hybrid = 규칙 + LLM Judge)

| 항목 | 규칙 검사 (1안, 결정적) | LLM Judge (2안, `prompts/quality_judge.md`) |
|---|---|---|
| Groundedness | 본문에 인용된 `evidence_id`가 모두 `evidence_pool`에 있고 REFERENCE에 수록됐는가. 본문 수치가 인용 근거 `excerpt`에 있는가(`balance.py`의 `_numbers`/`_covered` 재사용) | 주장 문장 샘플이 인용 출처로 추적되는가 (1~5) |
| 중립성 | 금지 표현 사전("더 우수", "추천", "순위", "1위", "승자", 총점) 0건. `final_assessment`에 합산 점수 없음 | 특정 기술 우열·추천 뉘앙스가 있는가 |
| 편향 통제 | 기술별 출처(publisher) ≥ 2, 항목별 pro·con 양쪽 존재, 단일 출처 항목 비율 상한 | 유리한 근거 편중·단일 출처 의존 여부 |
| 관점 커버리지 | 기술 2 × 관점 4 모두 `final_results`에 NA 아닌 결과 ≥ 1, 보고서에 4관점 절 존재 | 4관점이 실질적으로 서술됐는가 |

통과 조건: 규칙 4항목 전부 PASS **and** Judge 4항목 모두 임계(예 ≥ 4/5). Judge는 `with_structured_output`으로 Pydantic 스키마 강제, temperature 0.

### 4.2 미달 시 라우팅 (`route_after_quality`)

| 미달 항목 | 되돌아가는 노드 | 전달 값 |
|---|---|---|
| Groundedness · 편향 통제 | `plan_tasks` (재수집 계획) | 미달 셀을 `RetryTarget(kind="research")`로 |
| 관점 커버리지 | `score_dispatch` | 빠진 (관점, 기술) |
| 중립성 | `synthesize_report` 재생성 | Judge 피드백을 프롬프트에 주입 |
| `quality_round == max` | `END` | 미달 항목을 보고서 SUMMARY 끝에 "품질 평가 미달 항목"으로 기록 |

### 4.3 테스트

- `tests/test_quality.py`: 가짜 모드에서 (a) 통과 케이스, (b) 금지 표현 주입 → `synthesize_report` 재실행, (c) 한도 도달 → 정상 종료. `KV_FAKE=1`에서 Judge는 규칙 결과를 그대로 반환하는 fake로 대체.

### 4.4 Judge / Gate 분리 — Deterministic Boundary (수업 Appx. B)

- `judge_node`(LLM, 확률적 판정)와 `gate`(순수 함수, `add_conditional_edges`)를 **물리적으로 분리**한다. LLM에게 "검증하고 다음 단계도 정해라"는 금지.
- 결정론 층이 먼저 거르고(규칙 4항목), 통과한 것만 Judge로 보낸다. Judge 출력은 Pydantic 스키마로 강제하고, 라우팅은 그 값만 읽는 순수 함수.
- 종료는 코드 상수로만: `MAX_QUALITY_ROUNDS`, `MAX_RETRY_ROUNDS`, `recursion_limit`, LLM 호출 상한. 모델 판단에 종료를 위임하지 않는다.
- Evaluator-Optimizer 피드백: 미달 사유·Judge 코멘트를 `quality_verdict.feedback`에 담아 `synthesize_report` 프롬프트에 주입(Generator에게 피드백 전달).

### 4.5 Fan-out/Fan-in 설계 고려사항 (수업 4-4-2) — README "동시 처리"에 적을 내용

| 고려사항 | 적용 |
|---|---|
| Reducer 정합성 | 공유 키 전부 reducer(`operator.add`, `merge_tasks`, `merge_dict`). worker는 담당 키만 반환 |
| Concurrency | `config={"configurable": {"max_concurrency": N}}` — Tavily·OpenAI rate limit 기준 N을 `runtime.yaml`에 |
| 부분 실패 | 체크포인터 필수(성공 브랜치 보존), 실패 브랜치만 재시도. 정책: 1회 재시도 → 제외 |
| 타임아웃 | worker별 timeout, 초과 시 failed 처리 후 진행 |
| 멱등성 | 검색 캐시(`.cache/`) + `evidence_id`/`duplicate_group` 중복 제거 → 재시도해도 중복 누적 없음 |
| 순서 비의존 통합 | `latest_results`는 round 기준, `evidence_for`는 id 기준 → 도착 순서 무관. join 노드는 `defer` |
| 관측성 | `node_status`·`errors`로 브랜치 단위 추적, LangSmith에서 가장 느린 브랜치 식별 |

### 4.6 Output 부실 방지 (수업 4장 TIP)

- `evidence_pool`은 **raw 보관·압축 금지**, 에이전트 간 통신용 요약은 `EvidenceBrief`로 별도 필드. 이미 계약에 분리돼 있음 — 유지.
- `synthesize_report`는 `final_assessment` 요약만 보지 말고 `evidence_pool`·`final_results`를 **직접 참조**해 조립한다(현 `report.py` 방식 유지). 프롬프트에 분량·필수 항목 명시.
- 체크포인터로 중간 결과 보존.

### 4.7 WebSearch 노드 (수업 3장 TIP)

- 모든 셀이 웹검색을 하지 않는다 — `plan_tasks`가 채널을 정한다(필요한 셀만 웹). 이것이 "동적 처리"의 근거 중 하나.
- raw 검색 결과는 `collect_evidence` worker 안에서 소비·폐기하고, 상위 State에는 원문 확인을 거친 `Evidence`만 올린다(Searcher → Reasoner 격리). 현 구조와 일치 — README에 명시.
