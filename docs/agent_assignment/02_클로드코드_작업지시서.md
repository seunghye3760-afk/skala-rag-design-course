
## Step 2 — plan_tasks + 동적 fan-out + fallback

```
src/kv_eval/orchestrator/plan.py 와 dispatch.py 를 구현해.
plan.py
- plan_tasks(state) -> {"task_plan": [...], "step_count": 1}: tech_briefs·rubrics["query_rules"]·only_criteria·
  이전 round 결과(retry_targets, node_status)를 보고 셀(기술×항목)별 SubTask를 만든다.
  (2026-10-07 변경) LLM 플래너(prompts/plan.md, 구조화 출력)가 항목마다 기술별 채널과 쿼리 템플릿 쌍(1~3, 쌍 하나 = worker 하나)을
  정한다. 코드는 가드만: 빠진 셀 보완, {tech} 자리 강제(두 기술 같은 템플릿), 셀당 상한(plan.max_subtasks_per_cell).
  LLM 실패 → plan.llm_retry 회 재시도 → 루브릭 기본 템플릿 비상 계획 + decision_log "plan_fallback_default".
  retry round 에서는 retry_targets 의 research 대상만, 사유(비판 근거 없음 등)를 플래너 입력에 넣어 쿼리를 다시 짠다.
- replan(state): 품질 미달 셀만 다시 pending 으로 (quality_verdict.failed_items 기준).
dispatch.py
- fan_out_collect(state) -> list[Send]: task_plan 에서 status=="pending" 인 것만 Send("collect_evidence", CollectTask).
  CollectTask 에 channels 를 넘길 수 없으면 rewrite_hint 에 채널 문자열로 전달 (계약 파일 수정 금지).
- collect_worker(task): 기존 evidence.collect.collect_evidence 를 감싸는 래퍼. 예외 시 1회 재시도, 재실패 시
  node_status[task_id]="excluded", errors 에 {"task_id","node","type","message","ts"} 추가, info_gap 용 RetryTarget 반환.
  성공 시 node_status[task_id]="done". 반환은 자기 키만.
- score_worker(task): agents.score_task.score_task 래퍼. 동일 정책, 실패 시 해당 항목 NA 결과 생성.
- evidence_join / score_join: defer=True 로 등록 (모든 브랜치 완료 후 1회).
- configs/runtime.yaml 에 fallback: {worker_retry: 1, on_failure: "exclude"} 와 concurrency: {max_concurrency: 8} 추가.
- 진행 로그는 progress.step 사용, 결정(계획·제외·재시도)은 observability.decision(run_id, node, decision, reason) 으로
  outputs/runs/<run_id>/decision_log.jsonl 에 append.
tests/test_plan.py: (a) fan-out 수가 셀 수가 아니라 플래너의 템플릿 수로 정해짐, (a') 가드가 누락 셀 보완·상한 적용, (b) tech_brief 에 따라 채널이 달라짐,
(c) collect_worker 가 2회 실패하면 excluded + errors 1건 + 나머지 브랜치는 정상 누적. KV_FAKE=1 기반.
```

완료 조건: `uv run pytest` 전체 통과, fan-out 수가 입력에 따라 달라지는 테스트 존재, 실패 worker가 전체를 멈추지 않음.

## Step 3 — 품질 평가 노드 + Loop (plan mode)

```
plan mode로 계획 먼저. src/kv_eval/orchestrator/quality.py 와 prompts/quality_judge.md 를 구현해. 00_과제_프롬프트.md §4 그대로.
- evaluate_report(state) -> {"quality_verdict": ...}: 규칙 4항목을 코드로 판정.
  groundedness: report.md 본문에서 evidence_id 패턴을 뽑아 evidence_pool·REFERENCE 절에 모두 있는지, 수치는
  rules/balance.py 의 _numbers/_covered 를 재사용해 인용 excerpt 와 대조.
  neutrality: 금지 표현 사전(configs/quality.yaml 에 목록: "더 우수","우월","추천","순위","1위","승자","총점","종합 점수" 등)
  0건 + final_assessment 에 합산 점수 없음.
  bias: 기술별 publisher ≥2, 항목별 pro·con 양쪽 존재 비율 ≥ 임계(quality.yaml), 단일 출처 항목 비율 ≤ 임계.
  coverage: 기술 2×관점 4 모두 NA 아닌 final_results ≥1, 보고서에 4관점 절 제목 존재.
  규칙 전부 PASS 일 때만 judge_node 호출.
- judge_node(state): LLM(llm.chat_model, with_structured_output) 으로 4항목 1~5점 + 코멘트. KV_FAKE=1 이면 규칙 결과를
  그대로 5점으로 반환. 판정만 하고 라우팅은 하지 않는다.
- route_after_quality(state) -> str: 순수 함수. passed → END. 미달 항목별:
  groundedness/bias → "replan", coverage → "score_dispatch", neutrality → "synthesize_report".
  quality_round >= quality.max_rounds(2) → "finalize" (SUMMARY 끝에 "품질 평가 미달 항목" 기록 후 END).
- synthesize_report 재생성 시 quality_verdict.feedback 을 prompts/synthesis.md 에 주입(기존 함수 시그니처 유지, 래퍼로).
tests/test_quality.py: (a) FAKE 통과, (b) 보고서에 "더 우수" 주입 → neutrality 실패 → synthesize_report 재실행 후 통과,
(c) 항상 실패하게 만들면 quality_round 2 에서 finalize 로 정상 종료(무한 루프 없음).
```

완료 조건: 테스트 3종 통과, `judge_node` 와 `route_after_quality` 가 별도 함수, 종료 상한이 상수.

## Step 4 — 그래프 조립 + 실행 스크립트 (plan mode)

```
src/kv_eval/orchestrator/graph.py 의 build_orchestrator_graph() 와 app_agent.py 를 만들어.
노드: load_config → load_rubrics → tech_research → plan_tasks →(conditional: pending 있으면 fan_out_collect, 없으면 score_dispatch)
→ collect_worker(Send) → evidence_join(defer) → score_dispatch →(fan_out_score) score_worker(Send) → score_join(defer)
→ balance_check →(route_after_balance: plan_tasks | score_dispatch | apply_rules) → apply_rules → synthesize_report
→ evaluate_report → judge_node(조건부) →(route_after_quality: replan→plan_tasks | score_dispatch | synthesize_report | finalize | END)
- compile(checkpointer=MemorySaver()) (SqliteSaver 는 선택). invoke config:
  {"configurable": {"thread_id": run_id, "max_concurrency": runtime.concurrency.max_concurrency},
   "recursion_limit": runtime.limits.recursion_limit, "run_name": run_id, "metadata": {"run_id": run_id},
   "tags": ["orchestrator", "kv-eval"]}
- status 갱신: 정상 종료 SUCCESS, info_gap/excluded 있으면 PARTIAL, 예외는 FAILED + errors.
- app_agent.py: app.py 와 같은 CLI(--criteria) + --thread 로 재개 지원. 끝에 run_id, fan-out 수(라운드별), retry_round,
  quality_round, status, report_path, PDF 쪽수를 출력.
- docs/main_graph_orchestrator.mmd 생성 후 graph.get_graph().draw_mermaid() 결과와 일치시키기.
tests/test_orchestrator_runs.py: KV_FAKE=1 로 --criteria TRL-1,DOM-4 전체 실행, report.md 에 "## SUMMARY" 와 "## REFERENCE" 존재,
status in {SUCCESS, PARTIAL}, decision_log.jsonl 생성.
```

완료 조건: `KV_FAKE=1 uv run python app_agent.py --criteria TRL-1,DOM-4` 가 보고서를 만들고 종료, 기존 `app.py` 동작 불변.

## 사람이 직접 하는 것 (Claude Code 밖)

1. `.env`에 `OPENAI_API_KEY`, `TAVILY_API_KEY`, `LANGSMITH_API_KEY`, `LANGSMITH_TRACING=true`.
2. `uv run python scripts/download_corpus.py` → `uv run python -m kv_eval.rag.index --model BAAI/bge-m3`.
3. `uv run python eval/retrieval/run_selection.py` → Hit@K·MRR 값을 README에 기입.
4. `uv run python app_agent.py` 실제 실행 **3회**(PassK=3) → 모두 SUCCESS/PARTIAL, 품질 PASS, 무한 루프 없음 확인.
5. LangSmith에서 `tracing-1.png`(전체), `tracing-2.png`(plan_tasks→fan-out 개수), `tracing-3.png`(balance/quality 재작업 분기) 캡처. fan-out 수·재작업 횟수를 README "동적 처리"에 기입.
6. PDF 쪽수 ≤ 10 확인, `docs/main_graph_orchestrator.png` 렌더.
7. PR(`feat/agent-orchestrator` → main) 템플릿 체크, 리뷰 1명.
8. `Agent_판교_6반_안서현+이민기+박재흥+김승혜.zip` = Git 링크 + PNG + PDF → Slack 스레드, DAY 2 퇴근 전.
